# Требования к ПО «СТО»

Версия 0.2. Статус Core обозначает базовый объём, Deferred — отложенную функцию, Proposed — предложение. Критерии ниже предназначены для приёмки проектируемого приложения.

## Функциональные

| ID | Статус | Требование | Приёмка |
| --- | --- | --- | --- |
| FR-001 | Core | Приёмщик создаёт и находит карточки клиента и автомобиля. | Две карточки с одинаковым VIN создать нельзя. Автомобиль находится по VIN и госномеру. |
| FR-002 | Core | Сотрудник ведёт справочники неисправностей, постов и рабочих мест. | В записи можно выбрать существующий пост. В наряде можно выбрать существующее рабочее место. |
| FR-003 | Core | Приёмщик создаёт и переносит запись в интервале 08:00–20:00. Система исключает пересечения на одном посту. | При существующей записи 09:00–10:00 запрос 09:30–10:30 отклоняется, а 10:00–11:00 разрешён. |
| FR-004 | Core | Приёмщик оформляет наряд по существующей записи, указывает клиента, рабочее место и вид работ. | Номер выдаётся после сохранения. Назначение рабочего места, уже занятого активным заказом, отклоняется. |
| FR-005 | Core | Сотрудник ведёт каталог и добавляет запчасти в состав заказ-наряда с количеством, ценой и скидкой. | Две детали по 15 BYN со скидкой 5 BYN дают стоимость строки 25 BYN. Изменение каталожной цены не меняет сохранённую цену строки. |
| FR-006 | Core | Сотрудник переводит наряд по допустимым состояниям и фиксирует итоговую стоимость. | Переход «Новый → Оплачен» отклоняется. Отменённый наряд имеет нулевую стоимость. |
| FR-007 | Deferred | Система напоминает клиенту о предстоящем визите. | Одно уведомление на текущую запись, за сутки до визита. |
| FR-008 | Proposed | Приёмщик выгружает сохранённый наряд в PDF. | Номер, клиент, автомобиль, работы, позиции и итог совпадают с сохранёнными данными. Выгрузка не изменяет наряд. |

## Нефункциональные

| ID | Требование | Приёмка |
| --- | --- | --- |
| NFR-001 | Целостность при одновременной записи. | При двух конкурентных запросах на пересекающиеся интервалы одного поста сохраняется максимум один. |
| NFR-002 | Разграничение доступа к данным. | До входа карточки клиентов недоступны. Клиентский браузер не имеет прямого доступа к PostgreSQL. |
| NFR-003 | Плановый показатель отклика — не более 2 с по 95-му процентилю для поиска автомобиля и просмотра наряда при 5 активных сотрудниках и 10 000 нарядов. | Замерить оба сценария на стенде при заданной нагрузке. |
| NFR-004 | Сохранность данных при перезапуске и отказе записи. | Подтверждённый наряд доступен после перезапуска приложения. Неуспешная операция не оставляет его частично заполненным. |
