# PostgreSQL для данных СТО

## Контекст и постановка задачи

Записи, посты, заказ-наряды и запчасти образуют связанные сущности. Требуются ограничения данных и транзакции.

## Драйверы решения

Целостность, параллельная работа сотрудников, использование имеющейся схемы.

## Рассмотренные варианты

PostgreSQL, SQLite, отдельные файлы.

## Итог решения

Использовать PostgreSQL. Выбор подтверждается существующим DDL. Внешние ключи, CHECK и частичные индексы выражают правила на уровне хранилища.

## Последствия

Нужен сервер PostgreSQL. Данные можно проверять независимо от формы ввода.

## Подтверждение

Проверить ключи и ограничения в DDL. При приёмке проверить отказ записи с отсутствующим внешним ключом.

## Связанные требования

FR-001, FR-002, FR-004, FR-005, NFR-004. [Каталог требований](../src/requirements.md).
